# FinSight Frontend Workspace

The typed TypeScript + Vite build pipeline that consumes the Spring
backend's `/v3/api-docs` and ships typed wrappers for the 50+
`fetch()` call sites in `backend/src/main/resources/static/app.js`.

This is the RFC 002 deliverable. See
[`docs/rfcs/RFC-002-openapi-typescript-codegen.md`](../docs/rfcs/RFC-002-openapi-typescript-codegen.md)
for the full design.

## Layout

```
frontend/
  package.json             npm scripts + dependencies
  tsconfig.json            strict TypeScript config
  vite.config.ts           Vite + Vitest config
  src/
    api/
      index.ts             createApiClient, ApiError, once()
      auth.ts              typed auth wrappers
      research.ts          typed research wrappers
      watchlist.ts         typed watchlist wrappers
      generated/
        schema.d.ts        generated by `npm run api:generate`
    main.ts                entry point; sets window.finsight.api
    types/
      window.d.ts          ambient Window declaration
  test/
    once.test.ts
    api-error.test.ts
    api-auth.test.ts
```

## Local development

```bash
# 1. Install dependencies (only once per checkout)
npm install

# 2. Generate the typed schema from a running backend
npm run api:generate

# 3. Type-check the workspace
npm run typecheck

# 4. Run the unit tests
npm test

# 5. Build the bundle (output: frontend/dist/app.bundle.js)
npm run build
```

## CI

- `api-lint` (added in PR #34's CI) regenerates the schema and
  fails the build if the committed `schema.d.ts` is not
  byte-identical.
- The `ci.yml` workflow runs `npm ci && npm run typecheck && npm test`
  on every push and PR.

## Open the bundle in the Spring app

The static `index.html` still loads `/app.js` for the duration of
the migration. The new bundle is served from
`backend/src/main/resources/static/app.bundle.js` once the
`frontend-maven-plugin` runs as part of `mvn package`. The shim
in `app.js` calls `window.finsight.api` for the migrated call
sites; the rest continue to use `fetch()`.
